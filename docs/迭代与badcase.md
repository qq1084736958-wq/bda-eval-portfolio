# 迭代与 Badcase · 智能经营数据问答助手

> AI 产品经理的核心不是"功能上线即结束"，而是用评测与反馈把失败**定位到具体链路节点**，再决定改 Prompt、知识、规则还是交互。本文记录代表性 Badcase 的 tracing 归因、修改动作与回归标准。
> 评测方法与真实基线见 [评测体系设计与发现](评测体系设计与发现.md)。

---

## 一、评测如何驱动迭代（方法）

```
准备评测案例 → 运行完整基线 → 自动检查确定性字段 → 人工/自动质量评审
 → 按类别与优先级统计 → 查 trace 定位失败节点
 → 修改规则/路由/检索/上下文/Prompt/展示 → 只重跑失败项 → 必要时再跑完整集
```

关键原则：**不说"笼统优化 Prompt"**，而是先用 trace 把失败归因到路由 / 规格化 / 检索 / 权限 / 回答 / 状态的某个节点，再做针对性修改和回归。

## 二、代表性 Badcase（产品迭代）

### Badcase A · 复合问题 0/5 通过（架构级问题）
**问题示例**：查询 2026 年第二季度本部门采购金额，同时告诉我达到多少必须公开招标。

| 项 | 内容 |
|---|---|
| 低分维度 | 路由正确性、任务完整性、证据支撑 |
| 现象 | 只回答金额或只回答制度，无法同时完成两个子任务 |
| tracing 归因 | 系统只有单一路由，一个请求只能进结构化查询或 RAG |
| 修改节点 | 统一问答服务、复合意图拆分、结果协议、移动端展示 |
| 修改动作 | 拆分业务与知识子任务，分别做权限过滤，组合为**双来源答案** |
| 回归标准 | 金额正确、现行制度引用正确、旧版本不出现、两类来源分区展示 |
| 产品判断 | **不能只改主 Prompt，必须改工作流架构** |

### Badcase B · 回答正确，但用户不知道下一步
**问题示例**：查询 2030 年我们部门采购金额。

| 项 | 内容 |
|---|---|
| 低分维度 | 可行动性（最低人工评分 1 分） |
| 现象 | 正确返回"无数据"，但没建议如何调整 |
| tracing 归因 | 失败状态 Prompt 只约束"不编造"，未区分失败原因与动作 |
| 修改节点 | 状态原因码、无数据 Prompt、移动端操作按钮 |
| 修改动作 | 明确当前查询条件、建议调整年份；为权限/无依据/未支持/异常分别配置动作 |
| 回归标准 | 正确性不降，可行动性≥3，平均分≥4 |
| 产品判断 | **正确拒答只是安全底线，解释原因 + 引导行动才是产品体验** |

### Badcase C · 模糊追问丢失上下文
**问题示例**：先查"本部门年度采购金额"，再追问"按项目给我排一下"。

| 项 | 内容 |
|---|---|
| 低分维度 | 上下文控制、路由正确性 |
| 现象 | 追问被当新问题，重复澄清部门/指标/时间 |
| tracing 归因 | 会话只存文本，未把上一轮任务规格用于下一轮 |
| 修改节点 | 会话状态、上下文选择、任务规格覆盖规则 |
| 修改动作 | 保留上一轮指标/部门/项目/时间/维度，只覆盖本轮明确修改字段 |
| 回归标准 | 查询范围正确继承，且不把未知实体强行映射为已有项目 |
| 产品判断 | **多轮能力的核心是保存可执行任务状态，而非聊天气泡** |

## 三、本次评测新发现（我实跑评测时定位的问题）

> 以下为我在运行真实基线（被测 DeepSeek-V3.2，80 条标注用例）时**亲自定位**的问题，是"评测驱动发现缺陷"的直接证据。

### 发现 1 · 口径歧义是头号真实痛点（跨源三处印证）
"**采购金额是否包含暂估金额**"这一个问题，同时出现在：
- **评测失败**：`NOD-010` 该题未能给出可靠回答；
- **未知问题池**：真实用户复现 **4 次**；
- **用户反馈**：被标记 `INACCURATE`（"采购金额和采购系统里看到的数不一致"）。

一个问题三处印证，说明它不是偶发，而是**真实、高频、影响信任**的口径缺口。
→ **优化建议**：把高频口径（暂估/中标/预算差异）固化为知识点，并在金额答案中**主动回显口径版本**，而非等用户追问。

### 发现 2 · 制度/招标知识覆盖不足
"单项采购达到多少金额要公开招标""公司有哪些采购方式""例外情况有哪些"等多条 RAG 题失败（`RAG-003/004`、`CTX-006`），且在未知问题池中反复出现。
→ **优化建议**：按未知问题频次优先补齐招标阈值、采购方式、例外审批等制度文档，并建立别名/口径映射。

### 发现 3 · 多轮追问存在真实崩溃缺陷
评测中 `CTX-007`（"批准前可以先拆分采购吗"）触发产品代码**空指针崩溃**（上下文继承处对上一轮时间范围未做空值防护）。
→ **优化建议**：修复上下文继承的空值处理，并把该用例纳入回归。这是"评测不是摆设、真的在抓 bug"的最硬证据。

### 发现 4 · 最弱质量维度是"依据充分性"（4.15）
五维质量评审中，"依据充分性"均分最低（4.15），典型是结构化"排名/汇总"类答案结论对、但来源/口径呈现不足（`STR-006`、`AQ-NRM-003/004`）。
→ **优化建议**：排名类答案补充口径说明、记录数与完成情况。

## 四、迭代产出的结构化沉淀
- **真实问题回流评测集**：从未知问题池/反馈/日志回流 66 条候选，去重分桶、标注扩充（见 `../eval-dataset/`）；
- **两层指标 + 自动 LLM-as-Judge + 回归基线**：把每次修改是否"改好/改坏"变成可量化的事；
- **优化清单**：上述发现按优先级进入 [PRD](PRD.md) 的里程碑。
