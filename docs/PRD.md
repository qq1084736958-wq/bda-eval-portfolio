# 产品需求文档（PRD）· 智能经营数据问答助手

> 版本 v1.0 · AI 产品经理（实习）· 本文为产品需求与方案说明，评测口径见 [评测体系设计与发现](评测体系设计与发现.md)，技术链路见 [Agent 工作流与架构](agent-工作流与架构.md)。
> 数据边界：全部为可重复生成的**模拟经营数据与模拟制度文档**，用于验证链路与口径，非真实企业数据。

---

## 1. 背景与问题

企业管理者和项目人员查经营信息时，通常要在报表系统、项目台账、采购数据和制度文件之间来回切换：
- **指标查询**依赖人工记住入口、指标名与筛选条件（时间、部门、项目），容易遗漏或口径不一致；
- **制度解释**依赖经验，且容易引用过期版本；
- **权限差异**：不同角色可见的部门、项目和金额精度不同，"能回答"不等于"可以回答"；
- **AI 幻觉**：直接把问题丢给大模型，即使没有依据也会给出看似合理的答案，影响决策可信度。

错误回答会带来四类成本：**决策风险**（金额/口径错）、**合规风险**（引用过期制度/泄露越权字段）、**信任损失**（无来源无法复核）、**重复沟通**（只说"没数据"，用户不知如何继续）。

**问题定义**：如何让管理者用自然语言获得"**有结论、有依据、有权限边界、知道下一步**"的经营信息，而不是一段无法验证的 AI 文本。

## 2. 产品目标与非目标

### 2.1 目标
1. 用自然语言完成经营指标查询与企业制度问答，覆盖结构化、知识、追问与复合四类任务。
2. 回答**可追溯**：附数据口径、来源记录、文档版本与引用片段。
3. 回答**权限受控**：角色决定可见范围与金额精度，越权不泄露。
4. 失败**可解释、可行动**：区分无数据/无依据/无权限/未支持/异常，并给出下一步。
5. 具备**可观测与可评测**闭环：Trace、未知问题池、反馈与离线评测驱动迭代。

### 2.2 非目标（明确不做）
- 不是把大模型接到聊天框的通用机器人；
- **不让模型计算经营金额、自由判断权限或凭常识解释制度**（这些交给确定性系统）；
- 不接入真实企业生产数据库；
- 当前不做开放式多 Agent 自主规划（见 §6 的架构取舍）。

## 3. 用户画像与场景

| 用户 | 任务状态 | 核心诉求 | 权限特征 |
|---|---|---|---|
| 高管 | 快速掌握经营概况 | 跨部门指标、排名、趋势 | 可看全公司授权数据 |
| 部门经理 | 掌握本部门项目与采购 | 本部门金额/项目/结果/制度 | 仅本部门授权范围 |
| 项目专员 | 执行具体项目 | 本人参与项目及后续操作 | 仅授权项目，金额可区间化/隐藏 |
| 运营管理员 | 维护问答与知识质量 | 日志、未知问题、反馈、知识库、评测 | 可管运营配置，≠可见全部业务明细 |

**典型触发时刻**
- 开会前确认某部门本季度采购金额与项目排名；
- 看到采购结果后追问归档期限与制度要求；
- 只说"按项目排一下""那例外情况呢"，需继承上一轮上下文；
- 查询越权范围/未来时间/未支持指标/知识库缺失内容，需解释原因而非编造；
- 运营发现重复未知问题或低质回答，需查 Trace、改配置并回归验证。

## 4. 范围与 AI 边界

**AI 负责（处理模糊性）**：理解自然语言中的指标/部门/项目/时间/维度；处理别名、错别字、模糊表达；判断任务路由；对制度文档语义检索并基于片段生成表达；在保证事实与权限后优化结论与下一步表达。

**确定性系统负责（处理确定性）**：金额计算、记录数、排序聚合；身份/部门/项目范围/金额精度；文档启用状态/版本/生效日期/权限；引用文档 ID/来源记录/同步批次；无数据/无依据/无权限/异常的状态判定。

> 核心原则：**AI 处理模糊性，系统处理确定性**。经营数值与权限属高风险确定性信息，不交给模型推断。

## 5. 功能需求

### 5.1 手机端（完成用户任务）
- 内置四类测试身份；首页按角色显示常用问题、权限范围与数据更新时间；
- 问答页保留历史、瀑布流追加；支持多轮上下文、推荐追问、错别字修正与条件澄清；
- 结构化结果支持金额/明细/表格/柱状/折线/环形图；
- 知识回答展示文档标题、版本、标题层级、页码或片段；
- 复合问题把"经营数据结果"与"制度解释"分区展示；
- 按失败原因提供：编辑问题/选项目/调时间/查权限/重试/反馈；
- 快捷反馈、详细反馈、历史会话、浏览器语音输入（不支持时回退文字）。

### 5.2 运营后台（形成闭环，16 模块）
问答运营（问答日志、未知问题池、用户反馈、预设问题）；知识与模型（知识库、检索调试、Prompt 工程台、指标口径、词库别名、业务术语）；系统管理（用户权限、数据源监控、审计日志、系统设置含模型 Key）；总览工作台；评测中心（P0/P1/回答质量专项、人工复核、失败回归）。

### 5.3 Agent 工作流（概述）
```
用户问题 + 登录身份 + 会话上下文
 → 问题归一化（错别字/别名/模糊条件）
 → 任务路由（STRUCTURED / RAG / COMPOSITE）
 → 任务规格化（指标/时间/部门/项目/维度，含多轮继承）
 → 权限过滤后的结构化查询  /  metadata 过滤 + 召回 + 重排的 RAG 检索
 → 确定性数值与来源校验 / 基于证据的受控回答生成
 → 答案组合与失败状态映射
 → 手机端展示（结论/图表/引用/下一步） + Trace/运营后台
 → 评测 / Badcase 归因 / 回归
```
每个节点的输入输出、评价标准与典型失败见 [Agent 工作流与架构](agent-工作流与架构.md)。

## 6. 架构取舍：固定 Workflow，而非多 Agent

当前任务路径稳定，可预先拆成识别/查询/检索/校验/展示等节点，**固定 Workflow 比多 Agent 更合适**：成本更低、延迟可控、每个节点更易追踪与评测。
只有当任务扩展为跨多系统开放式分析、需动态选工具、制定计划并验证多步结果时，才引入 Sub-agent 或 Agent Team。当前版本不为技术包装增加不必要的 Agent 复杂度。

## 7. 权限与安全设计

权限**同时作用于结构化查询与 RAG 检索**，不靠前端隐藏：
1. 登录身份确定角色/部门/项目授权；
2. 结构化查询在 SQL 条件中限制范围；
3. 金额按角色返回精确值/区间/隐藏；
4. RAG 在向量召回与候选过滤阶段排除无权限文档；
5. 结果卡片不展示受限数据/图表/引用标题/片段/相似度；
6. 日志记录所用权限规则，但不记录 API Key 等敏感配置。

**失败状态机**（"没找到"不是同一种）：

| 状态 | 用户解释 | 下一步 |
|---|---|---|
| 条件不完整 | 缺指标/项目/部门/时间 | 补充或选择条件 |
| 业务数据为空 | 已按条件查询但无记录 | 调整时间/部门/项目 |
| 知识库无依据 | 可访问范围内无可靠制度 | 换问法或反馈补文档 |
| 权限不足 | 当前账号无权访问 | 查看权限/联系管理员 |
| 未支持问题 | 当前版本无对应指标/领域 | 改问已支持内容/提需求 |
| 系统异常 | 服务/网络/依赖不可用 | 保留问题并重试 |

## 8. 非功能需求
- **可追溯**：每次问答写入 `traceId`，记录路由、意图、指标、权限规则、来源与状态；
- **可观测**：未知问题池、反馈、问答日志、数据源同步批次与更新时间；
- **稳定性**：失败状态确定性判定；多轮以"任务规格"而非仅聊天文本继承上下文；
- **安全**：角色鉴权（JWT）、审计日志；密钥仅存本机、不入库不入前端；
- **可评测**：离线标注集 + 真实问题回流 + 自动/人工质量评审 + 回归基线。

## 9. 成功指标（评测口径）

以可复现的离线评测为准（真实运行 · 被测 DeepSeek-V3.2 · 80 条标注用例）：

| 层 | 指标 | 当前基线 |
|---|---|---|
| 确定性 | 路由准确率 | 95.0% |
| 确定性 | 状态准确率 | 92.5% |
| 确定性 | RAG 引用命中率 | 87.9% |
| 确定性 | 结构化取值正确率 | 100% |
| 质量 | 五维综合均分 / 通过率 | 4.58 / 5 · 87% |

> 口径说明与发现详见 [评测体系设计与发现](评测体系设计与发现.md)。指标均标注数据集规模、被测/评审模型与日期；未执行的指标不写成真实准确率。

## 10. 里程碑与后续方向

| 优先级 | 方向 | 目的 |
|---|---|---|
| 已完成 | 手机端 + 后台 + RAG + 权限 + 评测闭环本地可运行 | 打通端到端链路 |
| 已完成 | 真实问题回流评测集 + 两层指标 + 自动 LLM-as-Judge + 回归基线 | 把"看起来答得顺"变成可度量 |
| P0 | 口径知识固化（暂估/中标/预算差异主动回显） | 修复头号真实痛点 |
| P1 | 补齐招标/采购方式等制度知识与别名映射 | 降 RAG 失败 |
| P1 | 修复多轮追问上下文继承崩溃并纳入回归 | 稳定性 |
| P2 | 真实小范围试用 | 收集真实问题分布与新 Badcase |

## 11. 风险与边界（诚实声明）
- 数据为模拟数据，用于验证链路与口径，非真实企业数据；
- DeepSeek 是链路中的模型服务，非自训练/优化基础模型；
- 质量分来自自动 LLM 评审，尚未与人工校准，建议抽样对齐；
- 不声称真实企业上线、用户增长或商业转化。
