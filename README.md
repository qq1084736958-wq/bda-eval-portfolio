# 智能经营数据问答助手 · 评测体系与产品实践

> 面向企业管理者的**可控 AI 经营问答**产品中，我作为 AI 产品经理（实习）参与产品设计，并独立搭建了它的**评测体系**：用自然语言查经营数据与制度知识，系统在**权限范围内**返回**可追溯、知道下一步怎么做**的答案，而不是一段无法验证的 AI 文本。
>
> 本仓库是该项目的**作品集**：展示产品设计思路 + 我搭建的评测体系与真实评测结果。产品完整源码不在此公开（含企业场景模拟数据与协作代码）。

---

## 这个产品解决什么

管理者查经营信息时，常要在报表、台账、采购数据和制度文件之间来回切换；指标依赖人工筛选易遗漏，制度解释易引用旧版本，不同角色可见范围和金额精度不同，而 AI 即使没有依据也可能"一本正经地编"。

所以产品目标被定义为：**让管理者用自然语言获得"有权限、可追溯、知道下一步"的经营信息。**

| 用户 | 典型诉求 | 示例问题 |
|---|---|---|
| 高管 | 看全局、看趋势、看重点项目 | "今年采购金额最高的 5 个项目是什么？" |
| 部门经理 | 管本部门预算与项目 | "我们部门二季度采购金额按月看。" |
| 项目专员 | 查项目、理解口径 | "采购金额是否包含暂估金额？" |
| 运营管理员 | 维护问答质量与知识 | "哪些问题因为无依据被拒答？" |

## 产品处理链路

```
用户自然语言问题
   → 意图识别（经营数据 / 制度知识 / 上下文追问 / 复合问题）
   → 权限与数据范围校验（角色决定可见部门与金额精度）
   → 结构化数据查询  /  知识库 RAG 检索（按意图门控，该查才查）
   → 回答 + 数据口径 + 来源引用 + 下一步建议（无依据则明确拒答，不编造）
   → 可追溯 Trace / 未知问题回收 / 用户反馈 → 持续迭代
```

详见 [产品概述](docs/产品概述.md)。

## 我做了什么：把"看起来答得顺"变成"可度量的质量"

一个会聊天的系统不等于能上生产。我为它设计并落地了一套 **可复现、可追溯、能驱动迭代** 的评测体系，并跑出真实基线。完整方法与发现见 👉 **[评测体系设计与发现](docs/评测体系设计与发现.md)**。

### 真实基线（80 条标注用例 · 被测 DeepSeek-V3.2 · 2026-10-22）

**确定性层**

| 路由准确率 | 状态准确率 | RAG 引用命中 | 结构化取值正确 |
|---|---|---|---|
| 95.0% | 92.5% | 87.9% | 100% |

**答案质量五维**（跨家族 LLM-as-Judge · gpt-4.1-mini）

| 综合均分 | 通过率 | 正确性 | 清晰度 | 依据充分性 | 可行动性 | 表达自然度 |
|---|---|---|---|---|---|---|
| 4.58 / 5 | 87% | 4.81 | 4.57 | **4.15** | 4.50 | 4.87 |

### 评测驱动的发现（节选）
- **口径歧义是头号真实痛点**："采购金额是否含暂估金额"同时出现在 评测失败 + 未知问题池(复现4次) + 用户差评 三处。
- **制度/招标知识覆盖不足**：招标阈值、采购方式等多条 RAG 题失败且在未知问题中反复出现。
- **多轮追问稳定性缺陷**：评测中定位到一个真实崩溃 bug（上下文继承空值）。
- **最弱维度是"依据充分性"(4.15)**：答案有时结论对但来源/口径展示不足。

## 诚实边界
- 数据为**可重复生成的模拟数据**，用于验证链路与口径，非真实企业数据。
- 质量分来自**自动 LLM 评审，尚未与人工分数校准**；建议抽样人工对齐并报告一致率。
- 所有指标均标注数据集规模、被测/评审模型与日期；未执行的指标不写成真实准确率。
